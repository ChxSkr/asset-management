# 数字资产管理系统 — 项目总结

## 一、项目概述

**项目名称**：数字资产管理系统（Digital Asset Management System）

**项目目标**：构建一个面向团队/企业的数字资产管理平台，支持文件上传、分类管理、多版本控制、标签标注、全文检索和权限控制，帮助用户高效管理和追溯数字资产。

**开发模式**：前后端分离架构

| 项目  | 语言/框架                       | 构建工具   |
| --- | --------------------------- | ------ |
| 后端  | Java 17 + Spring Boot 3.2.5 | Maven  |
| 前端  | JavaScript + Vue 3.5        | Vite 8 |
| 数据库 | MySQL 8.0                   | —      |

## 四、功能模块

### 4.1 用户模块

| 功能        | 接口                              | 权限    |
| --------- | ------------------------------- | ----- |
| 用户注册      | POST /api/user/register         | 公开    |
| 用户登录      | POST /api/user/login            | 公开    |
| 获取个人信息    | GET /api/user/profile           | 登录用户  |
| 修改个人信息    | PUT /api/user/profile           | 登录用户  |
| 管理员创建用户   | POST /api/user/create           | admin |
| 管理员获取用户列表 | GET /api/user/list              | admin |
| 管理员查看用户详情 | GET /api/user/{userId}          | admin |
| 管理员修改用户信息 | PUT /api/user/{userId}          | admin |
| 管理员重置用户密码 | PUT /api/user/{userId}/password | admin |

**关键实现**：

* 密码使用 `BCryptPasswordEncoder` 加密存储

* 登录成功后返回 JWT Token（24小时有效期），包含 userId、username、role

* 个人信息接口默认屏蔽 password 字段

### 4.2 资产模块

| 功能    | 接口                               | 说明                                                  |
| ----- | -------------------------------- | --------------------------------------------------- |
| 上传资产  | POST /api/asset/upload           | multipart/file + name/categoryId/tagIds/description |
| 资产列表  | GET /api/asset/list              | 支持关键词、分类、文件类型、标签、时间范围筛选和分页                          |
| 资产详情  | GET /api/asset/{id}              | 含 tags 数组、categoryPath 分类路径                         |
| 编辑资产  | PUT /api/asset/{id}              | 可修改名称、分类、标签、描述                                      |
| 软删除   | DELETE /api/asset/{id}           | isDeleted 标记为 1                                     |
| 恢复资产  | PUT /api/asset/{id}/restore      | isDeleted 恢复为 0                                     |
| 永久删除  | DELETE /api/asset/{id}/permanent | 删除DB记录+硬盘文件+关联数据                                    |
| 回收站列表 | GET /api/asset/recycle           | 分页查询 isDeleted=1 的资产                                |
| 下载资产  | GET /api/asset/{id}/download     | 返回文件字节流，记录下载日志                                      |

**关键实现**：

* 文件上传校验：支持 PDF/DOC/DOCX/XLS/XLSX/PPT/PPTX/TXT/JPG/PNG/GIF/SVG/MP4/MP3/WAV/ZIP

* 文件大小限制 10MB

* 存储文件使用 UUID 重命名，避免文件名冲突

* 资产列表返回的数据中包含关联的标签信息

* 文件类型筛选支持分组：PDF、DOC（含docx）、IMAGE（含jpg/png/gif等）、VIDEO、AUDIO、ZIP、OTHER

* 下载时自动补充文件扩展名

### 4.3 版本管理模块

| 功能     | 接口                           | 说明       |
| ------ | ---------------------------- | -------- |
| 上传新版本  | POST /api/asset/{id}/version | 新版本文件+备注 |
| 获取版本历史 | GET /api/asset/{id}/versions | 按版本号倒序   |

**关键实现**：

* 上传资产时自动创建 `version_number=1` 的初始版本

* 每次上传新版本，资产的 `currentVersion` 递增

* 每次版本上传均更新资产主表的 `storagePath` 和 `fileSize`

* 操作日志记录 `VERSION_UPLOAD` 类型

### 4.4 分类管理模块

| 功能    | 接口                        | 说明                 |
| ----- | ------------------------- | ------------------ |
| 获取分类树 | GET /api/category/tree    | 递归构建树形结构           |
| 新增分类  | POST /api/category        | 可指定 parentId 创建子分类 |
| 编辑分类  | PUT /api/category/{id}    | 修改分类名称等            |
| 删除分类  | DELETE /api/category/{id} | 有子分类时拒绝删除          |

**关键实现**：

* 递归算法构建多级树形结构

* parentId=0 表示根级分类

* 删除保护：存在子分类时拒绝删除

### 4.5 标签管理模块

| 功能   | 接口                   | 说明       |
| ---- | -------------------- | -------- |
| 标签列表 | GET /api/tag/list    | 含实时关联资产数 |
| 新增标签 | POST /api/tag        | —        |
| 删除标签 | DELETE /api/tag/{id} | —        |

**关键实现**：

* 通过查询 `asset_tag` 关联表实时计算每个标签的关联资产数

* 资产-标签为多对多关系，通过中间表维护

### 4.6 全局搜索模块

| 功能   | 接口              | 说明                    |
| ---- | --------------- | --------------------- |
| 全局搜索 | GET /api/search | 支持关键词+分类+类型+标签+时间组合查询 |

### 4.7 日志管理模块

| 功能   | 接口                     | 权限    |
| ---- | ---------------------- | ----- |
| 操作日志 | GET /api/log/operation | admin |
| 下载日志 | GET /api/log/download  | admin |

**操作日志类型**：UPLOAD、UPDATE、DELETE、RESTORE、PERMANENT\_DELETE、VERSION\_UPLOAD

## 五、数据库设计

### 5.1 数据表清单

| 表名              | 说明       | 关键字段                                                                                       |
| --------------- | -------- | ------------------------------------------------------------------------------------------ |
| `user`          | 用户表      | userId, username, password(加密), role, realName, status                                     |
| `asset`         | 资产表      | assetId, assetName, fileType, fileSize, storagePath, categoryId, currentVersion, isDeleted |
| `asset_version` | 资产版本表    | versionId, assetId, versionNumber, storagePath, uploadUserId, versionNote                  |
| `asset_tag`     | 资产-标签关联表 | id, assetId, tagId                                                                         |
| `tag`           | 标签表      | tagId, tagName                                                                             |
| `category`      | 分类表      | categoryId, categoryName, parentId, sortOrder                                              |
| `operation_log` | 操作日志表    | logId, userId, operationType, description, operationTime, ipAddress                        |
| `download_log`  | 下载日志表    | logId, assetId, userId, downloadTime, ipAddress                                            |

### 5.2 表关系

```
user (1) ─────< asset (N)             [上传者]
category (1) ──< asset (N)            [分类]
asset (1) ─────< asset_version (N)    [版本]
asset (N) >──── asset_tag ────< tag (N) [多对多标签]
user (1) ─────< operation_log (N)     [操作者]
user (1) ─────< download_log (N)      [下载者]
asset (1) ─────< download_log (N)     [被下载资产]
```

## 六、安全设计

| 安全措施    | 实现方式                                        |
| ------- | ------------------------------------------- |
| 身份认证    | JWT Token（Bearer 模式），24小时过期                 |
| 密码加密    | BCryptPasswordEncoder（Spring Security）      |
| CSRF 防护 | 禁用 CSRF（前后端分离 + JWT 无状态）                    |
| 会话管理    | STATELESS（无状态，不创建 Session）                  |
| CORS 跨域 | 允许所有来源访问 /api/\*\*                          |
| 权限控制    | 拦截器注入 userId + role，Controller 层校验 admin 权限 |
| 文件安全    | 扩展名白名单 + 大小限制 10MB                          |
| 统一响应    | Result 包装类，code=200 成功，4xx 客户端错误，5xx 服务端错误  |
| 全局异常    | RuntimeException→400，Exception→500          |
| SQL 注入  | MyBatis-Plus LambdaQueryWrapper 参数绑定        |

## 九、开发过程关键问题与修复

| 编号 | 问题                                   | 原因                                                  | 解决方案                                          | 状态 |
| -- | ------------------------------------ | --------------------------------------------------- | --------------------------------------------- | -- |
| 1  | 标签管理"关联资产数"始终显示为空                    | 后端 TagServiceImpl.getList() 未计算 assetCount，前端绑定为空字段 | 在 getList() 中通过 assetTagMapper 实时查询每个标签的关联资产数 | ✅  |

| 4  | 资产删除功能失效                             | 后端接口及数据库操作存在缺陷                                      | 修复 softDelete 逻辑，实现 isDeleted 标记更新            | ✅  |
| 5  | 文件类型选择框与实际类型不一致                      | 前端筛选传值与后端类型映射不匹配                                    | 后端实现分组映射（IMAGE→jpg/png/gif等, DOC→doc/docx）    | ✅  |

| 7  | 上传资产页面分类选择框显示"无数据"                   | 数据库分类表未初始化数据                                        | 指导用户通过分类管理页面手动创建初始分类                          | ✅  |
| 8  | 后端启动端口占用错误                           | 8080 端口被其他进程占用                                      | 结束占用进程后重新启动                                   | ✅  |
| 9  | Maven 启动 Spring Boot 插件失败（Java版本不兼容） | 环境变量中的 Maven 使用了低版本 JDK                             | 改用 `java -jar` 直接启动已编译的 jar 包                 | ✅  |

## 十一、项目成果与亮点

### 功能亮点

1. **完整的资产生命周期管理**：上传→编辑→下载→版本迭代→软删除→回收站→恢复/永久删除，全链路覆盖
2. **多版本管理**：支持同一资产多次更新，保留完整版本历史
3. **灵活的筛选系统**：支持关键词+分类+文件类型（含分组）+标签+时间范围 五种维度组合筛选
4. **实时标签统计**：标签管理页面实时展示每个标签的关联资产数量
5. **深色/浅色主题切换**：CSS 变量驱动，一键切换，Element Plus 全组件适配
6. **自适应侧边栏**：可折叠设计，节省屏幕空间
7. **完善的权限控制**：基于 JWT + role 的双层鉴权，管理员专属接口受保护
8. **全操作审计**：上传/编辑/删除/恢复/版本更新/下载 全操作记录 IP 和时间

## 十二、经验与展望

### 经验总结

1. **前后端接口联调应先约定好数据格式**，如在标签新增功能上，前后端参数格式不统一导致了额外排查成本
2. **数据库初始化数据应纳入项目启动流程**，分类初始数据缺失影响用户体验
3. **文件类型分类映射应集中管理**，避免前后端各自维护导致筛选不一致
4. **日志记录应尽早规划**，后期补充操作审计功能增加了改动量

### 未来可优化方向

1. **引入 Swagger/Knife4j** 自动生成 API 文档
2. **补充单元测试**（JUnit 5 + MockMvc + Vitest）
3. **引入 CI/CD**（GitHub Actions 自动化构建与测试）
4. **文件预览功能**（在线预览 PDF/图片/视频）
5. **批量操作**（批量删除/移动/修改标签）
6. **文件去重**（基于 MD5 哈希避免重复上传）
7. **Elasticsearch** 替代 MySQL LIKE 查询，提升全文搜索性能
